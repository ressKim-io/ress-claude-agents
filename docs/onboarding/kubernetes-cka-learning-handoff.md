# Kubernetes·CKA 학습 프로젝트 시작 안내

작성일: 2026-09-28
상태: 요구사항 인계. 환경 구성 및 자산 적용 구현 계획은 아직 승인 전.

이 문서는 새 Codex 프로젝트에서 이전 대화를 읽지 않고도 학습 준비를 이어가기 위한 안내다.
사용자는 별도 학습 프로젝트를 직접 Codex에 등록한 뒤 그곳에서 시작할 예정이다.
등록할 프로젝트의 이름과 경로는 아직 정하지 않았다.
상세 협의 기록은 [학습 자산 적용 계획](../status/codex-learning-plan.md)에 있다.

위 사항은 다시 처음부터 선택하게 하지 않는다. 변경이 필요한 근거가 생기면 그 부분만 설명하고 확인한다.

## 2. 학습자의 출발점

- CKA 준비 목적이 아닌 프로젝트에서 EKS와 GCP의 Kubernetes를 사용한 경험이 있다.
- 백엔드팀과 ArgoCD 설정을 함께 했으며 Trivy 등 연동 경험도 있다.
- 명령어 사용은 검색을 많이 참고했고, 직접 작성·조작하는 데는 아직 익숙하지 않다.
- Obsidian에서 Kubernetes 내부 동작을 다시 깊게 공부했다.
- 프로젝트 경험과 이론 노트가 있다는 이유만으로 CLI 숙련도나 시험 준비 완료를 가정하지 않는다.
- 입문 이론 전체를 반복하기보다 기존 학습과 짧은 재현 실습을 연결해 부족한 부분을 찾는 방향을 제안한다.

학습에 필요한 노드 조작·장애 재현 범위와 현재 버전의 공식 문서를 확인한 뒤 구성안을 제시한다.
Linux PC 전환은 현재 PC의 실제 제약을 확인한 다음 검토한다.

사용자는 CKA 시험 환경이 현재 PC보다 느리거나 불편하다고 들었다.
이는 우려 사항이며 실측 비교가 아니다. 공식 시험 환경·제약을 확인해 적응 연습의 범위를 정한다.
시험 환경 버전과 할인 일정은 이 문서만으로 확정하지 않는다.

## 5. 실습 진행 방식

확정된 것은 시범 후 사용자 재현 방식이다. 아래 세부 진행안은 제안이며 첫 실습 전에 조정할 수 있다.

1. 기존 이론 노트와 연결해 오늘 관찰할 현상과 성공 기준을 설명한다.
2. Codex가 명령의 의미, 대상, 예상 출력과 확인 방법을 설명하며 시범을 보인다.
3. 미리 정한 해당 실습 범위만 초기화한다.
4. 사용자가 직접 재현한다. 초기에는 명령어 참고 자료를 제공하고 점차 도움을 줄이는 방식을 제안한다.
5. 실제 결과와 사용자의 설명을 확인한다. 성공 여부와 헷갈린 부분을 따로 기록한다.
6. 검토할 정보·문제·해설 초안을 Obsidian의 합의된 별도 위치에 축적한다.

사용자 재현 단계에서 Codex가 대신 문제를 끝내고 사용자 숙련으로 기록하지 않는다.
진도 기준은 날짜나 명령 암기량만으로 정하지 않고, 결과를 재현하고 이유를 설명할 수 있는지로 협의한다.
환경 준비·변경·초기화의 구체적인 대상과 실행 권한은 구현 계획에서 정한다.
“새 환경”이라는 답변은 관련 없는 리소스 삭제나 모든 클러스터에 대한 변경 권한을 뜻하지 않는다.

## 6. 사이트 프로젝트와 콘텐츠 축적

장기적으로 CKA·CNPA·CNPE 등 CNCF 관련 자격증의 한국어 정보·자체 제작 예상문제·해설 사이트를 만들 계획이다.
국내 정보가 부족하다는 것은 사용자의 문제 인식이며 시장 조사는 아직 하지 않았다.

- 먼저 본인이 공부하며 사용하고 부족한 점을 확인·보완한다.
- 이어서 다른 한국인 수험생에게 공개하는 방향이다. 공개 시점과 품질 기준은 아직 미정이다.
- 학습이 지루해질 때 사이트 프로젝트를 병행하며 환기한다.
- 콘텐츠는 이번 학습부터 Obsidian에 별도로 모은다. 검토한 내용만 나중에 사이트로 옮긴다.
- 사이트 구현, 로그인·결제·배포 설계와 Go·Rust 세부 자산 적용은 첫 단계 범위에 포함하지 않는다.

콘텐츠 형식 제안: 주제와 학습 목적, 공식 출처·확인일, 문제 조건, 풀이·해설, 실습 검증 여부, 검토 상태.
이는 아직 확정된 스키마가 아니다. 기존 개인 이론 노트를 자동으로 공개하거나 사이트로 전송하지 않는다.

## 7. 새 프로젝트에서 시작할 순서

1. 사용자가 등록한 실제 프로젝트 경로와 그곳의 지침을 확인한다.
2. 이 문서를 읽고 이미 확정된 내용을 짧게 요약한다.
3. OrbStack 상태, 도구 버전과 가용 자원을 읽기 전용으로 확인한다. 관련 공식 문서와 기존 학습 자료도 필요한 부분부터 읽는다.
4. 아래 미정 사항 중 첫 환경 구성에 필요한 것부터 채팅으로 한두 가지씩 묻는다.
5. 변경 파일 목록, 자산 적용 방법, 실습 구성, 검증 기준을 포함한 구현 계획을 제시한다.
6. 3개 파일 이상 변경은 계획 승인을 받은 뒤 시작한다. 새 의존성은 버전과 대안을 제시해 먼저 확인받는다.
7. 첫 시범·초기화·사용자 재현이 가능한지 실제로 검증한다. 실패하면 원인과 현재 PC의 제약을 기록한다.

### 남은 질문

- 실습 환경 준비와 초기화를 Codex가 실행할 정확한 범위는 무엇인가?
- 첫 실습에서 어떤 참고 자료와 힌트 수준을 제공할 것인가?
- Obsidian 콘텐츠 폴더 이름·문서 형식과 기록 시점은 어떻게 정할 것인가?
- 첫 실습 주제와 Kubernetes 자산을 무엇으로 선정할 것인가?

프로젝트 경로가 정해지기 전까지 임의로 새 채팅·저장소·클러스터를 만들지 않는다.
커밋·push·외부 게시도 별도 요청 없이 실행하지 않는다.

## 8. 현재 상태와 검증의 한계

전역 개인 지침 저장과 PC 일부 정보 조회, Obsidian 일부 조회는 수행했다.

빌드·테스트 및 실제 실습: 실행 안 함. 문서의 존재를 환경 구성 완료로 해석하지 않는다.
